# Recall

Generated by `npm run measure:recall`. Do not edit by hand.

The false-positive census in `FALSE_POSITIVES.md` inspects only lines the tool already flagged, so it measures precision and is structurally incapable of measuring what the tool misses. These labels were drawn without reference to any rule.

**Labelling criterion.** A line is `redundant` when a careful reviewer would say the agent can rediscover its content by listing the directory tree, reading a dependency manifest, or running the configured linter. Everything else - project-specific facts, non-obvious constraints, workflow instructions, prose and ordinary headings - is `legitimate`. REFINEMENT (disclosed): during measurement it became clear the original criterion did not separate a *descriptive* listing ("here is what the repo contains" - rediscoverable, redundant) from a *prescriptive* layout specification ("a skill MUST contain SKILL.md and scripts/" - not rediscoverable, legitimate). Three labels were revised under the refined criterion and are marked `revised: true` with their reasoning. The refinement was made because the distinction is real, not because it improved a number; both the pre- and post-refinement figures are reported in RECALL.md. Labels have been revised twice as the criterion sharpened; every revision is recorded in `revisionLog` and every revised item carries `revised: true`. Revisions were driven by discovering that the original criterion was ambiguous, not by whether a number improved - round 2 in particular corrected labels that had been scoring in the tool's favour.

## 1. Population sample (unbiased)

Every substantive line from all 28 context files in the corpus (3087 lines after removing blanks, fenced code and table separators), sorted by (repo, file, line) and sampled at a fixed stride of 19. Drawn with no reference to any rule.

- Lines labelled: **160**
- Redundant content base rate: **3.8%**

| | Inside a proposed deletion | Untouched |
|---|---:|---:|
| **Labelled redundant** | 5 | 1 |
| **Labelled legitimate** | 2 | 152 |

- **Recall 83.3%** (95% CI 43.6%–97.0%) — of redundant lines present, this share is caught.
- **Collateral 1.3%** — of lines labelled legitimate, this share falls inside a proposed deletion range and would be removed by `--fix`. Section-level findings delete a whole block, so this is not the same as precision (measured per finding in `FALSE_POSITIVES.md`) and is the number that matters when applying a patch.

> The interval is wide because redundant lines are rare: only 6 of 160 sampled lines are positives. A tighter population estimate needs a far larger hand-labelled sample. This is stated rather than hidden behind a point estimate.

## 2. Curated positives (higher power, biased by construction)

Lines hand-picked from the same corpus because they are clearly redundant, deliberately spanning forms the tool does catch (trees, path bullets, matching headings) and forms it may not (headings such as 'Navigation Map' and 'Skill Map' that the heading pattern does not match).

- Known-redundant lines: **15**
- Caught: **15** · Missed: **0**
- **Recall 100.0%** (95% CI 79.6%–100.0%)

> This is **not** population recall. The set was assembled by looking for redundant content, so it over-represents forms that are easy to find by eye. Read it as "of the clear-cut cases, how many are caught?".
