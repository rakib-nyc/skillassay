## Name-based duplication

Ling, Zhong & Huang (2026), arXiv:2602.08004 §3.2 report that across 40,285 marketplace listings, *"skills that appear more than once account for 46.3%"*. This section attempts to reproduce that on an independent corpus and reports whatever comes out.

**Method.** Lowercase each skill `name`, split on non-alphanumeric characters, drop explicit version markers (`v2`, `copy`, `backup`, …), rejoin. Two skills are duplicates when these canonical forms are equal. Bare digits and single letters are deliberately *not* dropped — `report-1` and `report-2` are a numbered series, not two copies of one skill.

| View | Population | In a duplicated-name cluster |
|---|---:|---:|
| Every `SKILL.md` file | 1022 | **74.5%** |
| Distinct skills (exact copies collapsed per repo) | 635 | **4.7%** |

- Distinct duplicated names: **359**

**Which number to compare.** The second row. A marketplace lists a skill once, but a repository routinely vendors the same skill into `.claude/`, `.codex/` and `.gemini/`. Counting those three files as three duplicates measures packaging convention, not ecosystem redundancy, and inflates the figure substantially.

**Do we reproduce 46.3%? No.** On the comparable view this corpus shows **4.7%** — an order of magnitude lower. The raw file count of **74.5%** is higher than the published figure, but it is measuring something else (per-harness packaging), so neither number confirms the paper.

The most likely reason is that the corpora differ in kind, not that either is wrong:

- **Source.** A marketplace aggregates independent authors publishing to one namespace, which is exactly the setting where the same idea gets re-listed under the same name. A GitHub repository is one author curating their own collection, and authors do not usually ship two skills with the same name on purpose.
- **Concentration.** 797 of 1029 files here come from a single repository (`alirezarezvani_claude-skills`), so this is closer to a measurement of that collection than of an ecosystem.
- **Unit.** The paper counts listings; this counts files. The dedup step above is an approximation of a listing, not the same object.

The honest conclusion: **this corpus cannot test the 46.3% claim.** Testing it would need marketplace listings, which is the corpus the paper used and which this audit does not have.
